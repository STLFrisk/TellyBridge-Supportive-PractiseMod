# TellyBridge Trainer — Minecraft 1.8.9 Forge 练习辅助

一个**纯客户端**的 telly bridge 练习仪表盘：把你自己的放块节奏、起跳时机、俯仰角和线路可视化出来，
方便对着数字改动作。不改变任何游戏行为。

* Minecraft：**1.8.9**
* Forge：**11.15.1.2318-1.8.9**
* 环境：Java 8
* 依赖：无（不需要 Mixin、不需要其他模组）

## 它做什么 / 不做什么

**做**：读你自己的按键、准星、世界方块变化，在屏幕上画数据和参考线。

**不做**（这些属于作弊，本模组刻意不实现）：

* 不自动放方块、不自动连点、不改 `rightClickDelayTimer`
* 不自动转向 / 不自动瞄准 / 不改俯仰角
* 不改触及距离（reach）、不改移动速度、不改跳跃
* 不向服务器发送任何额外数据包（除了你自己操作本来就会发的）

> 也就是说：**关掉这个模组，你的操作一模一样**，只是少了数字反馈。
> 即便如此，部分服务器 / 比赛对"任何客户端模组"都有规定，请先确认服务器规则再使用。

## 功能

### HUD 面板

| 指标 | 含义 |
| --- | --- |
| `Blocks` | 本次练习成功放下的方块数（以世界里真的出现方块为准） |
| `Time` | 从第一块到最近一块的耗时 |
| `Rate` | `Blocks / Time`，方块每秒，衡量推进速度 |
| `Jumps` | 本次练习的起跳次数 |
| `B/Jump` | 平均每跳放出几块 |
| `Miss` | 起跳后落地却一块都没放出来的次数（空跳） |
| `Air` | 本次跳跃还剩多少秒落地（用上一次真实滞空时长做基准）——telly 要在它归零前补到脚下 |
| `Blk` | 本次跳跃已经放了几块（落地后显示上一跳的） |
| `Spd` | 水平速度（格/秒）——回头放块时掉速就靠它发现 |
| `Cadence` | 相邻两次放块的时间间隔均值，也就是手速节奏 |
| `Jitter` | 间隔的标准差，越小说明节奏越稳 |
| `J>P` | 起跳 → 空中第一块 的延迟，telly 手感的核心指标 |
| `Pitch` | 当前俯仰角，配一条可自定义的靶带 |
| `Aim` | 落点提示：`R15 D7` = 还要右转 15°、下压 7°；`OK` = 准星已经会放到目标格 |
| 节奏条 | 最近 30 多次间隔的柱状图（越高越快，绿→红表示慢下来） |
| 按键行 | W/A/S/D、RMB、JUMP、SPR 的实时状态 + `AIR/GND` |
| 进度条 | 对着 `target` 目标方块数的完成度 |
| `Best` | 历史最佳速率 / 最长一次 / 最佳稳定性 |

> 打开背包 / 菜单时面板自动让位，但**聊天栏打开时仍然显示**（方便边查命令边看数据）。

### 落点提示（telly 的核心）

telly 的循环是「前冲 → 起跳 → 空中回头 → 把方块放到脚下那一格」。模组把这个动作拆成两个落点分别提示：

* **目标格**（世界里那坨**半透明绿色幽灵方块**）= **桥末端外侧那一格**，也就是你现在真正能放上去的下一块。
  它不是死板的"脚下那一格"：会沿着你的移动方向（站着不动时用朝向）从 0 格扫到 4 格，
  跳过实心桥体，取第一个"贴着已有方块、够得着"的空格——所以跳出 2~3 格也有提示，
  而且随着你越补越靠前，它会自动一格格跟过来。对上之后填充会变实一点。
* **瞄点**（世界里的白色小十字 + 屏幕上的绿色空心准星）= 想填这一格，必须点击
  「相邻支撑块朝向它的那个面」。取离眼睛最近的可点击面，那个面的中心就是准星该落的位置。

* **只在空中提示**：站在方块上（`GND`）不显示，起跳离地（`AIR`）才出现——
  桥面已经踩实的时候本来也没缺口要补。想让它在站着时也显示，用 `/telly hint air` 关掉这个限制。

所以屏幕上同时回答两个问题：

1. **该把准星转到哪** → 屏幕上那块绿色幽灵准星就是瞄点的投影位置，
   配合 `R15 D7` 数值：`R/L` 右转/左转多少度，`D/U` 下压/上抬多少度。
2. **这样转会放到哪** → 绿色幽灵方块是目标格；你自己准星的落点框
   对上了就直接重合（不再重复画）、放歪了会显示一个**蓝色框**；面板上 `Aim OK` 就是对上了。

瞄点在身后时（telly 转头 180°，最常见的情况），准星旁改为**左右三角 + 上下刻度**指方向。

### 世界内参考（全部可关）
* **绿色参考框**：你此刻准星会把方块放到的那一格（本地 rayTrace，纯粹是把你瞄准的位置画出来）
* **蓝色线框**：本次练习已放下的方块（回看线路直不直）
* **橙色折线 + 线框**：上一次破纪录的「幽灵路线」，用来复现自己的标准动作

## 命令（客户端命令，任何服务器都能用，不需要 OP）

主命令 `/telly`，别名 **`/tbt`**。走的是客户端命令处理器，**不发给服务器**——
所以在别人服里、没 OP、甚至服务器把聊天频率限到 1 条/秒时都能用。
支持 Tab 补全（打 `/tel` 按 Tab 能看到 `/telly`、`/tell`）。

不带参数直接打 `/telly` 就是帮助。

### 显示与面板

| 命令 | 参数 | 作用 |
| --- | --- | --- |
| `/telly hud` | `[on\|off]` | 开关 HUD 面板；不带参数 = 切换 |
| `/telly pos` | `<x> <y>` | 面板左上角位置（按 GUI 缩放后的像素算，左上角是 `0 0`） |
| `/telly scale` | `<50~300>` | 面板缩放百分比，默认 100，超范围自动夹紧 |
| `/telly hint` | `[on\|off]` | 落点提示总开关；不带参数 = 切换 |
| `/telly hint ghost` | — | 切换屏幕上的幽灵准星 |
| `/telly hint fill` | — | 切换目标格的半透明绿色填充（关掉只留线框） |
| `/telly hint air` | — | 切换「仅空中提示」（默认开；关掉后站在方块上也会提示） |
| `/telly hint line` | — | 切换眼睛 → 瞄点的引导线 |

### 练习记录

| 命令 | 作用 |
| --- | --- |
| `/telly start` | 手动开始一次记录（默认 `practice.autoStart=true`，放第一块会自动开始，一般不用手动） |
| `/telly stop` | 结束本次并结算纪录，聊天栏打印本次数据 |
| `/telly reset` | 清空**本次**记录，不动历史最佳（等价热键 `R`） |
| `/telly stats` | 看历史最佳：速率 / 最长 / 稳定性 / 每跳，以及累计练习次数与方块数 |
| `/telly stats reset` | 清空历史最佳与幽灵路线，并立即写盘 |

### 幽灵路线

| 命令 | 作用 |
| --- | --- |
| `/telly ghost` | 不带参数 = 切换显示 |
| `/telly ghost on` / `off` | 显式开关 |
| `/telly ghost save` | 把**当前这次**的走位与放块位置存成幽灵（等价热键 `J`） |
| `/telly ghost clear` | 清空已存的幽灵 |
| `/telly ghost xray` | 切换穿透显示（穿墙也能看到幽灵） |

### 练习参数

| 命令 | 参数 | 作用 |
| --- | --- | --- |
| `/telly pitch` | `<min> <max>` | 俯仰靶带，单位度，范围 `-90~90`；`min > max` 会自动交换 |
| `/telly target` | `<n>` | 一条练习的目标方块数，`0` = 隐藏进度条 |
| `/telly save` | — | 立即把配置与历史纪录写盘 |

### 使用示例

```
/telly pos 4 60            面板挪到左边偏下，躲开准星
/telly scale 80            缩小一点
/telly pitch 50 70         靶带收到 50~70 度
/telly target 60           这组练 60 块
/telly hint fill           关掉绿色填充，只留线框看形状
/telly hint air            允许站方块上也提示（默认是只在空中提示）
/telly ghost save          当前这趟手感好，存成幽灵
/telly stats reset         换个目标重新打纪录
```

### 说明

* 配置类命令（`hud` / `pos` / `scale` / `hint` / `pitch` / `target`，以及 `ghost` 的 `on|off|xray`）
  **立即生效并写入 `config.cfg`**，等于顺手执行了一次 `/telly save`。
* `ghost save` / `ghost clear` 写的是 `stats.json`（幽灵数据存在那儿）。
* `start` / `stop` / `reset` 只影响当前这次会话，不写盘。
* 同样的开关也能在 `config/tellybridge/config.cfg` 里手改，或用热键（见上一节）。

## 构建

已在 **JDK 8 (Temurin 1.8.0_432) + Gradle 4.10.3 + ForgeGradle 2.1-SNAPSHOT** 下实测通过
（`gradle build` → `compileJava` → `reobfJar`），产物在 `dist/TellyBridgeTrainer-1.8.9-1.0.0.jar`。

```bash
# 需要：JDK 8、Gradle 4.10.3
# Windows 下若 bundled 的 Gradle 还在，可直接用：
..\.tools\gradle-4.10.3\bin\gradle.bat build --no-daemon

# 或自己装好 Gradle 4.10.3 之后：
gradle wrapper --gradle-version 4.10.3   # 只需一次
gradlew build
```

几个坑，踩过才知道：

* **不能用 ForgeGradle 2.3+**——它在 `mappings` 阶段就抛
  `ForgeGradle 2.3.4 does not support Minecraft 1.8.9. MIN: 1.12`，必须用 **2.1-SNAPSHOT**。
* **必须 JDK 8**，JDK 17/21 跑不了 ForgeGradle 2.x 的工具链。
* `mappings` 用 `stable_22`（`stable_20` 也可以）。
* **版本号只有一个来源**：`gradle.properties` 的 `modVersion`。jar 文件名、`mcmod.info`、
  Java 里的 `TellyBridgeTrainer.VERSION` 都跟着它走；两边一旦对不上，`verifyVersion` 会让构建直接失败。
  （`@Mod(version = ...)` 要编译期常量，没法从 Gradle 注入，所以用校验代替代码生成。）
* ⚠️ **发布用 `gradle release`，别手工拷 `build/libs`。** `gradle runClient` 会把 `build/libs` 里的 jar
  覆盖回**未重混淆**的开发版（成员名是 `thePlayer` 这种 MCP 名），那个 jar 进正式客户端会崩。
  `release` 任务固定在 `reobfJar` 之后拷贝到 `dist/`，顺序不会错。
  手工核对的话：`build/libs/*.jar` 里应该能看到 `func_` / `field_` 这类 SRG 名。

## 怎么用它练（以下见仁见智，建议多自己摸索，以自身习惯为准。）

### 社区的三步递进

这个拆法来自 MCBBS 上一位老手的练法，个人觉得比自己瞎摸高效：

1. **后退跳搭** —— 按住 shift，一边后退跳一边往脚下放，先不管回头。
   目标是"边移动边连续放"这件事本身能跑通。
2. **起跳回头** —— 往前走，在起跳那一瞬间把视角甩到身后、放块、再甩回来。
   这一步练的是"回头这个动作不破坏节奏"。
3. **加量** —— 一次放两块 → 三块，直到能在一个滞空窗口里从桥末端一路补到脚下。

三个阶段的验收标准是同一个：**在落回起跳高度之前，把方块连到自己脚下**。
HUD 上对应的就是——`Air` 归零之前 `Aim` 应亮过 `OK`，且 `Blk` 达到这一跳需要的块数。

### 回头时的输入

MC 的移动是**相对视角**的：视角转多少，前进键就得跟着换。这是"回头放块时掉速"的根因——
人还在往前飞，但 `W` 已经不再指向桥的方向了，按住不放就会往斜向甚至横向滑。

一次跳跃里的三个阶段（以**向右甩**、沿 +Z 方向前进为例）：

| 阶段 | 视角朝向 | 该按的键 |
| --- | --- | --- |
| 起跳前 ~ 起跳 | 朝前（对着桥的方向，0°） | `W` |
| 甩到身后的那半圈（去程，**最容易掉速的一段**） | 朝侧面（约 90°） | `D`（向右甩）/ `A`（向左甩） |
| 已经完全背对 | 朝后（180°） | `S`（相对背对视角就是"向前"） |

**滑键顺序连起来就是 `W → D（或 A）→ S`**，松一个按一个，不要有全松的瞬间。

甩回前面（回程）同样会经过"朝侧面"的瞬间，但那时块已经放完，把 `S → D/A → W` 换回来就行，
不影响放块，所以不属于需要刻意练的那段。

`Spd` 就是盯这个的：正常 4.8 以上；掉到 4 以下说明你在转身的瞬间把箭头键全松了。

### 具体练法

1. **先固定节奏，再提速。** 开一个创造世界搭一条直线，什么都不改，先连放 30 块。
   盯 `Jitter`：目标是把抖动压下去（`Cadence` 均值可以先不管）。节奏一旦稳定，
   `Jitter` 会明显掉下来，柱状图会变得一样高。
2. **把 `J>P` 练成稳定值。** 起跳后第一块的延迟，绝对值因人而异，
   但**波动应该很小**。这个数忽大忽小，通常说明起跳和右键没对上。
3. **看 `B/Jump` 和 `Blk`。** `B/Jump` 是每跳的平均，`Blk` 是这一跳的实时值。
   每跳几块是你自己的风格，重要的是每一跳都一致。
4. **`Miss` 应该是 0。** 出现空跳说明起跳后没跟上，多数是视角没压下去或者右键晚了。
5. **用幽灵路线对齐动作。** 感觉好的时候按 `J` 存一条；以后每次破纪录会自动更新。
   开 `G` 打开幽灵，对比自己的走位与放块位置。
6. **加长距离。** `/telly target 30` 稳定达标后改 60、100；长距离更容易暴露节奏漂移。
7. **俯仰靶带要自己调。** 默认 `45~75` 只是起始参考值，用 `/telly pitch` 改成
   你自己"稳定出块"的那个角度区间，然后看 `Pitch` 是否一直在带内。
8. **用落点提示固定"回头点"。** 起跳后桥末端外侧那格会亮起绿色幽灵方块；
   把准星带到绿色幽灵准星上（`Aim` 变 `OK`），这一下右键就是干净的 telly 放置。
   先慢速练"起跳 → 看到绿块 → 补到位"，练顺之后 `J>P` 和落点会自然咬合。

## 已知限制

* 方块计数以**客户端世界里真的出现方块**为确认条件，所以有 1 tick 左右的确认延迟，
  高延迟服务器上会更慢（代码里给了 3 秒的确认窗口）。统计的是"实际进度"，不是"右键次数"。
* 视线外 / 服务器拒绝的放置不会被计入（这正是想要的行为）。
* `J>P` 依赖客户端 `onGround` 状态，在极端卡顿下可能少计一次起跳。
* 统计只做本次会话与历史最佳，不做逐块回放导出。
